# Бизнес-правило: Отслеживание статуса заказа

## Метаданные
| Поле | Значение |
|------|----------|
| **ID** | BR-CP-002 |
| **Версия** | 1.0 |
| **Дата создания** | 2026-08-30 |
| **Автор** | |
| **Кейс** | Чистый пиджак |

## Описание
Клиент отслеживает статус своего заказа в реальном времени

## Триггер
Клиент открывает раздел «Мои заказы»

## Предусловия
- Клиент авторизован
- У клиента есть хотя бы один заказ

## Основной поток
| Шаг | Действие | Кто выполняет |
|-----|----------|---------------|
| 1 | Открывает «Мои заказы» | Клиент |
| 2 | Загружает список заказов | Система |
| 3 | Показывает заказы со статусами | Система |
| 4 | Выбирает конкретный заказ | Клиент |
| 5 | Показывает детали и текущий статус | Система |
| 6 | Видит статус: Принят → В работе → Готов → Можно забирать | Клиент |

## Альтернативные потоки
### А1. Заказов нет
- **Привязка к шагу:** Шаг 3
- **Условие:** У клиента нет заказов
- **Шаги:** Система показывает «У вас пока нет заказов» + кнопка «Перейти в каталог»
- **Возврат к шагу:** Завершение (клиент переходит в каталог)

### А2. Фильтрация по статусу
- **Привязка к шагу:** Шаг 3
- **Условие:** Клиент хочет видеть только заказы со статусом «Готов»
- **Шаги:** Клиент выбирает фильтр → система показывает отфильтрованный список
- **Возврат к шагу:** Шаг 4

## Исключительные потоки
### Е1. Ошибка загрузки заказов
- **Привязка к шагу:** Шаг 2
- **Условие:** Сервер не отвечает
- **Реакция системы:** «Не удалось загрузить заказы. Попробуйте позже»
- **Результат:** Цель НЕ достигнута

## Постусловия
- Клиент видит актуальный статус заказа
- Клиент знает, когда заказ можно забирать

## Бизнес-правила и ограничения
- Статусы обновляются в реальном времени
- Push-уведомления при смене статуса
- Статус «Готов» означает, что заказ можно забирать

## Связанные требования
- FR-004: Клиент должен видеть статус заказа
- FR-005: Уведомления при смене статуса
