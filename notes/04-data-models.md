# Заметки: Модели данных

## Типы связей

| Связь | Описание | Пример |
|-------|----------|--------|
| 1:1 | Один к одному | Клиент → Паспорт |
| 1:M | Один ко многим | Клиент → Заказы |
| M:N | Многие ко многим | Заказы → Товары |

## Как определить тип связи
Задаём два вопроса:
1. "Сколько экземпляров В связано с одним А?"
2. "Сколько экземпляров А связано с одним В?"

## Пример
**Заказ ↔ Клиент:**
- У одного клиента много заказов → 1:M
- Один заказ у одного клиента → M:1
- Итого: Клиент 1:M Заказ

## Red Flags в модели данных

1. M:N оставлена напрямую без промежуточной сущности
2. Один и тот же факт хранится в нескольких местах
3. В одной сущности смешаны разные по смыслу объекты
4. Поля вида product1, product2, product3
5. Атрибут зависит от связи, но хранится "сбоку"

## Проверка модели
Прогнать через неё реальные сценарии, включая неудобные:
- Удаление
- Повторное использование
- Изменение статуса
- Исторические данные
- Несколько связанных объектов одновременно
