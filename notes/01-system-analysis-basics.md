# Заметки: Основы системного анализа

## Что делает системный аналитик

1. **Исследование и выявление потребностей** — услышать истинную проблему за запросом стейкхолдера
2. **Формализация требований** — перевод с бизнес-языка на технический
3. **Декомпозиция** — разбиение крупной задачи на атомарные части
4. **Валидация** — проверка требований на корректность, полноту, непротиворечивость

## Три измерения работы аналитика

| Измерение | Что это | Пример |
|-----------|---------|--------|
| Задача | Мыслительная операция | Выявить потребности |
| Артефакт | Осязаемый результат | Use Case, ER-диаграмма |
| Результат | Ценность для команды | Разработчик знает, что кодировать |

## Главное правило
Убрать любое звено — и ценность работы аналитика становится невидимой.

## Артефакты системного аналитика

1. Vision & Scope — границы системы
2. Реестр требований — ФТ, НФТ, User Stories
3. Модели данных — ER-диаграммы
4. API-контракты — OpenAPI, Swagger
5. Динамические схемы — BPMN, Sequence Diagram
6. SRS — спецификация требований

## Когда артефактов достаточно

1. Понятна бизнес-цель
2. Описаны основной и альтернативные сценарии
3. Зафиксированы входы/выходы и интеграции
4. Известны ограничения и допущения
5. Есть критерии приёмки
6. У команды нет блокирующих вопросов
