# Заметки: Use Cases и сценарии

## Структура сценария

### 1. Цель
Что хочет достичь пользователь

### 2. Предусловия
Что должно быть выполнено до начала

### 3. Триггер
Событие, запускающее сценарий

### 4. Основной сценарий (Happy Path)
Шаги, ведущие к цели (атомарные, по одному действию)

### 5. Альтернативный сценарий
Цель достигнута, но другим путём

### 6. Исключительный сценарий
Цель НЕ достигнута

### 7. Постусловия
Состояние системы после успешного завершения

## Типы сценариев

| Тип | Описание |
|-----|----------|
| Основной | Счастливый путь |
| Альтернативный | Другой путь к цели |
| Исключительный | Ошибка, цель не достигнута |

## Атомарность шага
Один шаг = одно действие одного участника

## Разница между условием и событием

- **Условие** — проверяемое логическое выражение (да/нет)
- **Событие** — произошедший факт, после которого процесс продолжается

## Пример
- "Пользователь нажал 'Оплатить'" — событие
- "Баланс карты достаточен" — условие

## Связи между сценариями

| Тип связи | Описание |
|-----------|----------|
| Ветвление | Разделение на разные пути |
| Возврат | Возврат в основной сценарий |
| Прерывание | Переход без возврата |
