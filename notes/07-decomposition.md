# Заметки: Декомпозиция системы

## Что такое декомпозиция
Разбиение системы на компоненты, которые можно разрабатывать и поддерживать независимо.

## Два главных принципа

1. **Low Coupling (Слабая связанность)** — компоненты минимально зависят друг от друга
2. **High Cohesion (Высокая связность)** — всё, что относится к одной задаче, собрано внутри одного компонента

## Принципы декомпозиции

| Принцип | Описание |
|---------|----------|
| Single Responsibility | Одна причина для изменения |
| Interface Segregation | Специализированные интерфейсы |
| Data Ownership | Компонент владеет своими данными |
| Ортогональность | Изменение не требует изменений в других |
| Абстракция | Сокрытие сложности за простым интерфейсом |

## Подходы к декомпозиции

| Подход | Когда применять |
|--------|-----------------|
| Функциональная | Планирование требований |
| Объектная | Проектирование БД |
| Модульная | Архитектура, интерфейсы |
| Структурная (WBS) | Планирование проекта |
| Процессная | Автоматизация бизнеса |
| По ролям | Разные задачи у ролей |

## Типичные ошибки

1. Передекомпозиция (слишком мелко)
2. Монолит под маской
3. Технические границы (по слоям)
4. Общая база данных
5. Забытые интерфейсы
